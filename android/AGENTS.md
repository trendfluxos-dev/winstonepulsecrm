# Android rules

- Call-log detection queues locally offline, retries after permission grant, and requires a signed-in agent before advancing its cursor; upload remains network-gated — why: offline work and signed-out scans must not silently disappear.

- Android recordings fall back to the phone's own call-recorder file (PhoneRecordingPickupWorker, recorder_source=phone_recorder) through the same upload queue; no match = no upload — why: Android 10+ blocks app call-audio capture.
- android/whisper is GPL-3.0 code copied from NotelyVoice (owner decision 2026-10-24); any APK linking it must ship with its full source offered, and the module stays unlinked from :app until minSdk 26, model delivery and 16 kHz PCM conversion are decided — why: license obligation and app-size impact.
- An Android release counts as ready only when docs/ANDROID_RELEASE_READINESS.md records signature/ID/version and device evidence for every gate row — why: a green CI build is not handset proof.
- The sandbox variant has a separate package, no INTERNET permission, production startup/receivers/services removed, and local synthetic JSON export only; summary states are simulations — why: test activity cannot reach live CRM or claim real AI processing.
- Native report UI instrumentation targets only sandbox, injects synthetic pending reports and never presses Submit — why: actual Compose coverage must not poll or mutate shared production CRM data.
- Native concise rejection mode uses ShortRejectionReport outcome defaults and omits sales/evaluation payloads; outcome corrections require confirmation and a new selection — why: no invented qualification or silent return to sales, while canonical server gates stay authoritative.
- Device token lives only in Keystore-backed EncryptedSharedPreferences (SecureTokenStore); plain copies are migrated then erased; queued work is stamped with the owner employee id and dropped if another account is signed in; outcomes carry a call_uid fixed at enqueue — why: tokens are not readable at rest and retries/account switches cannot misattribute work.
- Call audio (app recorder, phone-recorder pickup, upload) runs only after RecordingConsent is granted for the signed-in employee id and current consent version; mic/audio-file permissions are requested after consent and the pickup worker re-checks it — why: no recording without explicit, current, per-agent consent.

- Compose colours come only from ui/theme/Theme.kt tokens (light scheme; primary = charcoal button, WinGreen = gold accent); launcher icon is mipmap PNG + adaptive white tile from the brand logo, in-app logo is drawable-nodpi/winstone_logo — why: one palette matching the web CRM.
- Visual checks run in .github/workflows/android-brand-shots.yml (emulator, offline sandbox, synthetic data) and save screenshots to apk-builds/screens/<version>/ — why: artifact quota can block uploads and real CRM must not be touched.
- Official APK builds (android-apk.yml release job, android-release.yml tags) run only with all four WINSTONE_* signing secrets plus the WINSTONE_RELEASE_CERT_SHA256 variable, refuse any committed keystore, verify signer/package/version, write a .sha256 file, treat artifact-upload quota failure as a warning (APK kept on apk-builds or the draft release), and tags only create DRAFT releases; guarded by tests/android-release-gates.test.ts — why: no unsigned, wrongly signed or auto-distributed build, and storage quota is not a build failure.
- Outgoing calls: OFFHOOK is sent only as `initiated`; answered/unanswered and talk time come from the matched CallLog row via CallOutcomeWorker + CallHistoryEvidence (number tail + time window, talk ≤ observed window); no row/permission = `failed` + "not verified" note and report opened as not connected — why: Android never signals remote answer, and dial-to-hang-up time includes ringing.
- Sync failures are classified by `SyncErrorClassifier` from `SyncHttpException` status / IOException: permanent (400/403/404/409/410) stop as Failed with a bilingual action message; network/408/429/5xx retry; sign-in and briefing wait for the agent — why: no endless retries on impossible requests, and agents know what to do.
- Recordings are bound at enqueue to the originating agent (KEY_OWNER, never overwritten on resend) and call id; QueueOwnership.decideRecording drops ownerless/call-id-less or other-agent audio; PhoneRecordingMatcher.decide rejects other-number and multi-candidate matches (AMBIGUOUS → no upload) — why: delayed audio must never attach to another agent or the wrong call.
- `.github/workflows/android-ci.yml` is the PR/main check: read-only permissions, `./gradlew test assembleDebug assembleSandbox`, no secrets, no release, no pushes; guarded by tests/android-release-gates.test.ts — why: every Android change is compiled and unit-tested without touching signing.
